# フォルダごとの登録管理要件と仕様

## 目的と範囲

利用者は複数のフォルダを登録し、必要な登録だけを解除し、起動時の既定となるプライマリーフォルダを選べる。「編集」は登録追加・個別の登録解除・プライマリー選択・権限の再許可を指す。実フォルダの削除・改名・移動、表示名の独自編集、登録順の並べ替えは今回の操作に含めない。全登録の初期化を通常の管理操作として設けない。

登録のデータ構造と read 権限は [基本仕様](vimium-local-browser.md)、画面・保存・Viewer の接続は [統合仕様](local-browser-integration.md) を共用する。登録管理用に別のリストや保存先を作らない。

一覧の r / a / ?、常設 UI の除去と共通 CSS は [一覧 UI の改訂仕様](local-browser-ui.md) に従う。これは追加要件であり、末尾の既存 FM テスト成功には含まれない。

## 要件

| ID | 要件 |
| --- | --- |
| FM-01 | 登録一覧で、各フォルダの名前・識別補助・プライマリーの印・個別の登録解除操作を表示する。同名の別フォルダも見分けられる |
| FM-02 | 明示操作から 1 フォルダずつ追加できる。最初の登録だけ自動でプライマリーにし、その後の追加では現在値を維持する |
| FM-03 | 登録一覧での選択移動や検索では保存値を変えない。明示確定で選択したフォルダをプライマリーとして保存して開く |
| FM-04 | 解除前に対象を確認する。取消は登録・ID・順序・プライマリー・PDF 保存データを変更しない。解除にフォルダの読取再許可を要求しない |
| FM-05 | 解除は対象 1 件だけに適用する。残る登録の ID・handle・相対順序を保持し、次のプライマリーも同一の保存で確定する |
| FM-06 | 実ファイル、他の登録、一般設定、Vimium-C 接続設定、PDF のページ位置・マーク・ハイライト・パスワードを削除しない |
| FM-07 | 保存失敗・競合では旧状態を維持し、成功と表示しない。別タブの古い状態から登録を復活させたり、他の登録を消したりしない |
| FM-08 | マウスとキーボードの両方で管理できる。処理中・確認中・更新通知中は二重実行や対象の取り違えを防ぐ |

## 画面と操作

専用画面の「登録フォルダ一覧」を管理画面として使う。改訂後は子フォルダからも `r` または文字ボタンで直接移動でき、登録ルートで `h` を押しても同じ一覧に戻る。設定画面の「ローカル PDF を開く」から専用画面を開き、`r` でその登録一覧へ移って管理する。設定側に重複した登録編集 UI は設けない。一覧内の Settings ボタンは除去し、設定はブラウザ側の拡張アイコンの右クリック → オプションから開く。

| 操作 | 仕様 |
| --- | --- |
| 一覧の選択 | `j` / `k`・上下矢印・`gg` / `G`・行クリック。プライマリーの印と現在の選択を区別する |
| 登録名の検索 | `/` で現在の登録一覧を名前で絞る。未登録フォルダの探索や PDF 本文検索を行わない |
| 登録追加 | 改訂後は一覧の通常モード 4 状態で `a`、または「フォルダを追加」。標準 picker の 1 回の選択で 1 件を追加する。複数件は操作を繰り返す。取消では呼び出し元の状態を維持 |
| 既定の変更 | 入力モードを終了した一覧で `Enter` / `l`。読取許可と保存に成功してからプライマリーを変更して開く |
| 個別解除 | 各行の「登録解除」をクリック、または `Tab` でそのボタンに移動して `Enter`。確認画面を開く段階では保存しない |
| 解除確認 | フォルダ名と登録 ID、実ファイルと PDF 保存データが残ることを示す。プライマリーを解除するときは次の既定、最後の 1 件なら未登録になることも説明する |
| 解除の取消 | 確認の初期フォーカスは取消ボタン。取消ボタン / `Esc` で閉じ、一覧へフォーカスを戻す。確認中の一覧キー操作は処理しない |
| 再許可 | 権限確認画面の明示操作から `requestPermission({mode:"read"})`。ID を維持し、拒否や取消だけで登録解除しない |

行の操作ボタンは単なる行選択・開封と分離する。表示名は `handle.name` を文字として表示し、同名は区別できる短い ID、確認時は完全な ID を示す。独自の alias は保存しない。絞り込み中でも解除対象は表示位置ではなく登録 ID で固定する。確認表示後に別タブの変更が判明した場合は解除を実行せず、再読み込みと再選択を求める。

## 解除後の状態

| 解除対象 | 保存されるプライマリー | 画面 |
| --- | --- | --- |
| 非プライマリー | 現在の値を維持 | 残る登録一覧を表示 |
| プライマリー、他に登録あり | 登録順で最初に残る ID | 残る登録一覧を表示し、新しい既定を示す。自動で列挙・許可要求しない |
| 最後の登録 | `primaryId:null`、`roots:[]` | 未登録画面。追加は利用者の明示操作から行う |

次のプライマリーの権限が失効していても、さらに別の登録へ自動で飛ばさない。次回起動・明示確定時に通常の権限確認を行う。取消で戻れるフォルダが解除された場合、その古い一覧へは戻さない。他の登録を解除した場合は、残っている元のフォルダへの取消復帰を維持する。

別タブで表示中のフォルダや読み込み済みの PDF は強制的に切り替えない。更新通知を示し、新しい読取・移動・登録変更には明示的な再読み込みを求める。フォルダ登録の解除は VimDF の保存ハンドルを除く操作であり、ブラウザ側の権限を明示的に取り消す操作ではない。

## ID・保存・再登録

モデルは `{version:1,roots:[{id,handle}],primaryId}` のまま。IndexedDB の `{revision,state}` の比較と 1 transaction による commit で、対象の解除とプライマリー変更をまとめて保存する。commit が成功してから画面とメモリーへ新状態を公開する。未知の ID、処理中の再実行、古い revision からの保存を成功扱いにしない。

登録済みの同じ実フォルダを追加した場合は `isSameEntry()` で既存 ID を再利用し、順序とプライマリーを変更しない。一度解除したフォルダを登録し直すと新 UUID を作る。PDF identity は登録 ID と相対パスによるため、以前のページ位置などのデータは削除しないものの、新登録へ自動では関連付かない。再許可とプライマリー変更では ID が変わらず、従来の PDF 保存データを利用する。

## 復元できない DB の扱い

個別の権限失効は、正常に復元した登録一覧から再許可または解除できる。一方、登録 DB 全体の破損・不正な schema・将来バージョンなどで一覧を復元できない場合、個別解除で復旧できるとは保証しない。復元エラーを表示して登録変更を止め、再試行や通常の PDF 選択を案内する。自動的に空の登録で上書きしない。DB 全体の初期化・救出機能は今回の仕様に追加しない。

## 受け入れ条件と既存の証拠

| 条件 | 検査する結果 |
| --- | --- |
| 追加・重複 | 初回だけ既定化。追加は既定を維持。同じ実フォルダは ID を再利用、同名の別フォルダは別 ID |
| 選択・確定・権限 | 行選択と検索で保存なし。確定と明示再許可の成功でのみ既定変更。失効だけで登録を消さない |
| 個別解除・取消 | 同名の行や絞り込み後も確認した ID だけを解除。取消ボタンと `Esc` は副作用なし。既定解除時の次の値を確認画面に示す |
| 既定・最後の解除 | 非既定・既定・最後の 1 件の 3 分岐。残る ID と順序を保持し、自動の許可要求・列挙・実ファイル削除なし |
| 保存・競合 | 保存失敗で旧登録と復帰先を保持。2 タブの競合で古い全状態を上書きせず、再読み込み前の再実行を停止 |
| Viewer・再登録 | 解除で PDF 保存データと読み込み済み文書を消さない。再許可では同じ identity、解除後の再登録では別 identity |
| 操作・フォーカス | ボタンの `Enter` は 1 回だけ実行。確認中の一覧操作を停止。取消後のフォーカス復帰、長い一覧での選択行追従 |
| 利用不可・復元失敗 | API 不在ではフォルダ操作なし。DB 復元失敗で既存登録を空にしない。通常の PDF 選択を利用できる |

既存の Registry・Session・storage 検査に加えて、`local-browser-folder-management.test.mjs` の 6 件と `browser/local-folder-management.spec.mjs` の 18 件を追加した。テスト名の FM ID で以下の要件へ対応付ける。モデルと fake IDB の成功だけで DOM・native handle・Viewer の保持を証明せず、画面は本番実装を動かして検査する。

| 要件 | 自動検査 |
| --- | --- |
| FM-01 | 同名の native handle の識別表示・accessible name・各行の解除ボタン、設定画面から管理一覧への導線 |
| FM-02 | 既存の初回登録・取消と、新しい `a` による追加・重複選択。既存 ID と revision、プライマリーが変わらないこと |
| FM-03 | 既存の選択 / 検索 / 確定の分離と、再許可時の ID / PDF identity 保持、追加後の明示確定 |
| FM-04 | 同名・絞り込み後の解除対象 ID、確認前の保存なし、取消ボタン / `Esc`、次の既定・最後の登録の説明、失効した対象の無許可での解除 |
| FM-05 | 非既定・既定・最後の解除、残る handle / ID / 順序、同時に保存されるプライマリー、保存中の旧状態保持、未知 / 解除済み ID の拒否 |
| FM-06 | 実 OPFS ファイルの bytes、ページ位置 / マーク / ハイライト / パスワード / local・sync 設定の保持。他タブで解除しても読み込み済み PDF を保持。再登録の新 identity と旧マークの保存 |
| FM-07 | 遅い保存の失敗、native put 成功後の transaction abort、古い確認への別タブ更新、明示 reload と再選択、破損した保存値の保持、通常 PDF 選択による回復 |
| FM-08 | `Tab` / `Enter` での行操作、確認中の一覧キー停止、取消後のフォーカス、native 保存中の重複キーとボタン停止。長い一覧の選択行追従は既存の受け入れテストを共用 |

picker と permission は制御した境界を利用する。同名のフォルダは OPFS 内の異なる親に作り、保存・読取は native handle と実 IndexedDB で行う。transaction の遅延・abort は native request の境界だけを制御し、Registry・Session・DOM の状態や Viewer の保持を代替実装しない。

確認日：2026-10-10。新規モデル 6 件を含む Node 合計 182 件と build、ブラウザ全体の 45 件はすべて成功。個別管理の新規 18 件も全件成功した。`Esc` のフォーカス復帰、次の既定と最後の登録の説明、保存中断のエラー通知を実装し、画面の受け入れテストが検出した既存 8 件の不足も解消した。[テスト記録](local-browser-testing.md) に実装コミットと CI の根拠を残す。OS picker・権限保持と実 Vimium-C の版別動作は、代表環境での MR 手順として確認する。
