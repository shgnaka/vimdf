# ローカル PDF 一覧の表示・キー操作・ヘルプ・CSS 設定

整理日：2026-10-10。対象はフォルダ / PDF を選ぶ一覧画面、登録フォルダ一覧、両画面のヘルプと共通設定。この文書はデザイン検討で決まった追加要件であり、追加自動テストと本番実装を接続した。既存のテスト成功は追加要件の成功を意味しない。登録と保存の契約は [基本仕様](vimium-local-browser.md)、[フォルダ管理](local-folder-management.md)、[統合仕様](local-browser-integration.md) を継承する。表示・追加キー・ヘルプ・CSS の改訂についてはこの文書を優先する。

## 決定した表示方針

Vim のバッファ一覧とステータス行を参考にする。等幅文字、コンパクトな行、明確な選択行を基本とし、現在位置・一覧の種類・選択中・プライマリーを区別する。上部の VimDF ロゴと一覧内の Settings ボタンをなくす。常設の検索ボックスとキーバインド説明も表示しない。ステータス行はモード・現在位置・選択位置・件数を表示できるが、通常時にキー案内を並べない。未登録・権限確認・エラーの状況説明と実行 / 取消操作は必要なときに表示する。

Registered folders と Add folder はキー操作と同じ機能を持つ小さな文字ボタンとして残す。マウス利用と Tab によるフォーカスを維持し、大きなツールバーにしない。登録解除や再許可の既存ボタンも維持する。[デザイン確定案 v1](local-browser-design.md) に単一一覧、文字サイズ、余白、初期配色、全画面・例外状態の見本を具体化した。利用者による見本の確認は未完了で、本番の変更や承認済みの状態と混同しない。

設定は拡張機能共通の既存 Options ページを使う。ピンした拡張アイコンの右クリック → オプション、またはブラウザの拡張管理画面から開く。既存のアイコン左クリックはローカル一覧を開く動作を維持する。設定ページを開くための一覧内ボタンや新しいショートカットは追加しない。

## 一覧のキー操作

以下は修正後の契約。キー名は KeyboardEvent.key に従う。Ctrl・Alt・Meta 付きのキー、IME 合成中、入力欄やボタンがキーを所有する場合は一覧の通常コマンドへ配送しない。

| 場面 | キー | 動作 |
| --- | --- | --- |
| フォルダ内一覧 | r | 子フォルダの深さに関係なく登録フォルダ一覧を直接開く |
| 登録フォルダ一覧 | r | そのまま。選択・絞り込みをリセットしない |
| 権限確認 | r | 登録フォルダ一覧へ戻り、対象を選び直す。自動の許可要求なし |
| 未登録 | r | 変更なし。picker を開かない |
| 一覧の通常モード 4 状態 | a | フォルダ追加の標準 picker を明示操作から開く |
| 未登録 | Enter | a と同じ初回追加 |
| フォルダ内・登録一覧 | j / k、上下矢印 | 行選択。端で停止 |
| フォルダ内・登録一覧 | gg / G | 先頭 / 末尾。gg は独立した 2 回の押下 |
| フォルダ内 | Enter / l | 選択した子フォルダへ移動、または PDF を開く |
| フォルダ内 | h | 親へ移動。登録ルートでは登録一覧へ戻る |
| 登録一覧 | Enter / l | 選択した登録をプライマリーとして保存し、そのルートを開く |
| 登録一覧 | h | そのまま。OS の未登録の親へ移動しない |
| フォルダ内・登録一覧 | / | 下部の一時的な名前絞り込み入力へ移る |
| 名前入力 | Enter | 入力を終了するだけ。項目を開くには改めて確定する |
| 名前入力 | Esc | 入力を終了し、絞り込みを解除する |
| 絞り込みが残る通常一覧 | Esc | 絞り込みを解除する |
| 絞り込みのない登録一覧 | Esc | 切り替えを取消し、元のフォルダ内一覧へ戻る。復帰先がなければ留まる |
| 権限確認 | Enter / Esc | 明示再許可 / 登録一覧へ取消。既存の契約を維持 |
| 一覧の通常モード 4 状態 | ? | その画面のキーバインドヘルプを開く |

### 登録フォルダの切り替え

例：大学資料の子フォルダから r → j / k → Enter で別の登録へ移る。登録が多い場合は r → / → 名前入力 → Enter → Enter で選ぶ。前者の Enter は名前入力の終了、後者は登録の確定なので、入力確定とフォルダ切り替えを混同しない。

r は既存の Registered folders ボタンと同じ遷移を使う。遷移前のルート ID・相対位置・絞り込み・選択を保持し、取消で復元する。登録一覧に入ったときは現在のプライマリーを選び、登録順と Default 表示を維持する。開くだけ、選択するだけ、名前で絞るだけではプライマリーを保存せず、他の登録フォルダを列挙しない。

確定対象の読取権限と保存の成功後にプライマリーを変更する。権限がなければ確認画面に移り、次の Enter から許可を要求する。権限拒否・保存失敗・競合の既存の扱いを維持する。確定後は新しいルートで絞り込みを空にして先頭を選び、次回起動もそのルートから始める。

### フォルダ追加と解除

a と Add folder は同じ処理を使う。追加前に await を挟まず実際のキー / click ハンドラーから picker を開始する。API 非対応、初期化失敗、保存の競合、処理中など、既存の追加禁止条件では picker を開かない。権限確認からの a でも保留フォルダの再許可を自動実行しない。

picker の取消では呼び出した画面、位置、絞り込み、選択、保留中の許可対象と保存登録を維持する。初回追加だけ自動でプライマリーにして開く。追加登録が成功した場合は登録一覧を表示し、追加した行を選ぶ。既存のプライマリーは維持し、Enter / l で選ばれたときにだけ切り替える。重複登録は既存の ID・順序を維持し、その行を選ぶ。複数登録は 1 フォルダずつ繰り返す。

解除は各行の操作へ Tab で移動して Enter、確認画面で Tab / Enter / Esc により完結できる。新しい解除専用キーは追加しない。確認の初期フォーカスは取消で、実ファイルや PDF 保存データを消さない。r、a、確定、許可、取消、? のリピートで遷移や picker / ヘルプの開閉を繰り返さない。

## 名前絞り込みの表示

通常時は input を表示せず、Tab の対象からも外す。/ で下部のコマンド行に枠のない入力を表示する。入力中の r、a、?、j、k、h、l は文字でありコマンドを発火しない。文字列更新は input イベントを使い、IME 合成中の Enter / Esc を横取りしない。

Enter で入力を終了した後も絞り込みは残せる。通常の input は再び隠し、ステータス行に現在の絞り込み文字列を表示する。再度 / で同じ文字列を編集でき、Esc で解除すると元の一覧へ戻る。名前入力にフォーカスがある間に DOM を再生成して入力を失わない。対象は現在のフォルダ名・PDF 名、または登録名だけ。横断全文検索を追加しない。

## ? ヘルプとキーの所有者

一覧画面の ? は「ローカル PDF 一覧」のヘルプを開く。フォルダ内 / 登録一覧 / 未登録 / 権限確認で実際に使えるキーと状況を示す。通常画面の下部に案内を残さず、ヘルプ内に操作名とキーをまとめる。API 非対応時はフォルダ専用操作を表示・実行せず、利用できる PDF 選択の案内だけを示す。

PDF 表示中の ? は既存の Viewer ヘルプを開き、PDF 本文検索、移動、アウトライン、マークなど Viewer 側の内容を表示する。ローカル一覧の r / a を Viewer に追加しない。ヘルプの見た目と基本操作は共有できるが、一覧と Viewer のキー一覧を一緒に並べず、同じ DOM ID や document リスナーを重複登録しない。一覧の追加キーは宣言とヘルプ表を共通の定義から作る。

| 所有者 / 状態 | キー配送 |
| --- | --- |
| 解除・保存・パスワードなどのダイアログ | ダイアログが担当。背後の一覧 / PDF / ヘルプ操作を停止 |
| 入力欄・編集可能要素・IME | 文字入力と native 操作を優先。入力の Enter / Esc はその入力が担当 |
| 開いているヘルプ | ? / Esc で閉じ、j / k・上下・Ctrl-d / Ctrl-u・gg / G でヘルプをスクロール。/ はヘルプの説明を絞る入力 |
| files の通常モード | 一覧用ハンドラーのみ。Viewer は停止 |
| loading-pdf | 既存の取消操作を維持。一覧・Viewer の移動を実行しない |
| pdf の通常モード | Viewer の既存ハンドラーのみ。一覧用キーを実行しない |

ヘルプ中のキーで背後の選択、ページ位置、登録、絞り込みを変更しない。ヘルプ検索の Enter は入力終了、Esc は検索解除、検索していないヘルプの Esc / ? はヘルプを閉じる。入力中の ? は文字として扱う。閉じると元の画面・入力・選択へフォーカスを戻し、PDF の位置や一覧の絞り込みを初期化しない。

ヘルプ表示は semantic dialog として名前を持ち、フォーカスをヘルプ内に保つ。非表示のヘルプは Tab の対象外。処理中でも ? は読取専用ヘルプとして利用でき、処理完了時に勝手に閉じたり背後へフォーカスを奪ったりしない。ヘルプを開閉すると未完の gg などのキー列を解除し、別モードに持ち越さない。画面切り替え時はヘルプと検索などの一時状態を閉じてからキーの所有者を切り替える。

Vimium-C は専用画面を起動する入口として利用する。VimDF 内に Vimium-C のキーハンドラーを追加せず、外部起動で登録や picker を自動操作しない。Vimium-C の通常ページ上の r と、VimDF の一覧内の r は別のハンドラーの操作になる。

## 共通 Options と CSS カスタマイズ

Options は PDF Viewer とローカル一覧で共通の 1 ページ。項目を共通の外観、PDF Viewer、フォルダ管理への導線、Vimium-C 接続に分ける。フォルダ管理は専用画面の同じ登録一覧を使い、Options に別の登録データや編集 UI を作らない。Options から一覧を開き、r で登録一覧へ移れる。

共通の外観に「Custom CSS」の複数行編集欄、保存、CSS だけの初期化を置く。入力途中は画面へ適用せず、保存に成功した値だけを反映する。保存後は開いている一覧、ローカル PDF Viewer、通常 PDF Viewer、ヘルプへ反映し、ページ位置・選択・入力中の文字・フォーカスを保持する。設定変更ごとに runtime や style 要素を増やさない。

| 公開する対象 | 用途 |
| --- | --- |
| .vimdf-ui | 一覧・Viewer・ヘルプに共通する外観のルート |
| .vimdf-browser | フォルダ / PDF 選択画面と、その画面のヘルプ |
| .vimdf-viewer | 通常 / ローカル PDF Viewer と、その画面のヘルプ |
| .vimdf-help | ヘルプだけの外観 |
| .vimdf-browser .vimdf-row[aria-selected="true"] | 一覧の選択行 |
| .vimdf-statusline / .vimdf-commandline | ステータス行 / 入力・メッセージ行 |

安定した公開 CSS 変数は --vimdf-bg、--vimdf-fg、--vimdf-muted-fg、--vimdf-accent、--vimdf-selection-bg、--vimdf-selection-fg、--vimdf-focus、--vimdf-status-bg、--vimdf-status-fg。テーマの既定値と既存の色設定を基礎にし、公開ルートの変数で個別に上書きできるようにする。カスタム CSS は組み込みのスタイルより後で適用し、同じ詳細度ならカスタムを優先する。inline の設定値が公開変数の上書きを妨げないように接続する。

本番で利用できる例：

```css
.vimdf-ui {
  --vimdf-bg: #1e1e1e;
  --vimdf-fg: #d4d4d4;
  --vimdf-status-bg: #303030;
}
.vimdf-browser {
  --vimdf-selection-bg: #30445f;
  --vimdf-selection-fg: #ffffff;
  --vimdf-focus: #7aa2f7;
}
.vimdf-viewer {
  --vimdf-status-fg: #a6e3a1;
}
```

CSS は表示用のテキストとして適用し、HTML として挿入しない。構文の無効な規則はブラウザの CSS パーサーに従って無視され、他の有効な規則は利用できる。表示のカスタマイズでキー割り当て、フォルダ権限、登録、PDF の保存データを変更しない。非表示領域の入力停止・フォーカス停止と画面の排他表示は実装側で維持する。既存の保存済みハイライト色を書き換えない。

CSS は chrome.storage.local の独立したキー vimdf.customCss.v1 に {version:1,css:string} を保存する。未保存は空文字列で組み込みの外観を利用し、自動同期は今回の仕様に含めない。既存の一般設定は chrome.storage.sync、フォルダ handle は IndexedDB、接続設定と PDF パスワードはそれぞれ既存の保存先を維持する。sync の 1 項目あたりの上限で CSS の長さを小さく制限しないため local を選ぶ。

保存失敗時は未保存とエラーを表示し、編集テキストを保持する。開いている画面は最後に保存できた CSS のまま。読み込み失敗は組み込みの外観で操作可能にし、保存済み CSS を空で自動上書きしない。CSS 初期化はこの CSS キーだけを空にし、テーマなどの一般設定、登録、接続、PDF のページ位置・マーク・ハイライト・パスワードを変えない。

利用者の CSS を Options 自体へ適用しない。これにより一覧の配色を読みづらくしても、ブラウザ側から Options を開いて CSS を編集 / 初期化できる。CSS 同期・import / export・独自の任意キーマッピング編集は今回追加しない。

## 受け入れ条件とテスト化する項目

以下は追加テストの契約。テストの対応と実行結果は [テスト記録](local-browser-testing.md#ux-0113-の追加テスト) を参照する。実行結果は上記テスト記録を参照。既存の FM / UI / Viewer の検査は維持する。

| ID | 検査する結果 |
| --- | --- |
| UX-01 | 通常一覧にロゴ・Settings・常設検索欄・キー説明がなく、隠した入力が Tab の対象外。状態・現在位置・選択は識別できる |
| UX-02 | 深い子フォルダから r で登録一覧へ移り、選択と Enter だけで既定を保存して開ける。移動・検索だけでは保存なし |
| UX-03 | r で開いた登録一覧の Esc が元の位置・絞り込み・選択を復元。登録一覧の再度 r は状態を維持。未登録の r は picker なし |
| UX-04 | browse / roots / empty / permission の a が同じ追加処理。初回・追加・重複・取消・権限・保存失敗の各分岐で保存値と画面を検査 |
| UX-05 | / 入力の r / a / ? / j は文字。Enter は入力終了だけ、再度 Enter が確定。通常時に入力を隠しても絞り込みを識別・再編集・解除できる |
| UX-06 | 一覧の ? はその状態のヘルプ、PDF の ? は Viewer ヘルプ。ヘルプ開閉で背後の位置・選択・登録が変わらない |
| UX-07 | ヘルプ内の移動と / 検索がヘルプだけへ作用。? / Esc、フォーカス保持・復帰、gg の中断、キーリピートを検査 |
| UX-08 | IME・通常入力・ダイアログ・native button の操作を横取りしない。処理中の r / a / 確定を再実行・予約せず、? で処理やフォーカスを妨げない |
| UX-09 | files → loading-pdf → pdf → files で有効なキー所有者が 1 つ。r / a は PDF 上で登録操作を起こさず、j / k / / は現在の画面だけに作用 |
| UX-10 | 共通 CSS と画面別 CSS が通常 / ローカル Viewer・一覧・対応ヘルプに反映。公開変数を !important なしで上書きでき、既存色設定との優先順を検査 |
| UX-11 | CSS 保存成功後の反映、再起動後の復元、保存 / 読込失敗、無効な CSS 規則、空文字列、初期化を検査。入力・位置・登録・PDF 保存データを保持 |
| UX-12 | CSS 編集・初期化は Options から常に行え、利用者 CSS は Options を変えない。CSS 更新 / 画面切り替えで style とリスナーが増殖しない |
| UX-13 | 既存ボタンと追加キーの同値性、登録解除の Tab / Enter / Esc、API 非対応・DB 復元失敗時にフォルダ操作しないことを検査 |

モデルで r / a の状態遷移と取消を検査し、本番の拡張画面を動かす Chromium テストでフォーカス、排他表示、キー配送、computed style、保存後の反映を検査する。見た目の色やピクセル位置を固定値で決めつけず、公開変数への変更結果と操作の契約を調べる。OS picker のキーボード操作とブラウザ側のオプション導線は代表環境で確認する。

## 実装

r、全 4 状態の a、取消時の位置復帰、一覧 / Viewer 別の native modal help、一時入力、共通 Options の CSS 編集・local 保存・ライブ反映を接続した。追加は picker を呼ぶ直前に登録一覧へ切り替えず、成功後だけ切り替える。読取権限のない追加 handle は、既存登録がある場合に登録一覧へ残し、選択後の明示許可へ進む。初回の denied handle は既定として保存しない。等幅のコンパクトな一覧とステータス行を実装した。[デザイン確定案 v1](local-browser-design.md) は Viewer / Options を変更せず一覧側を具体化する確認用の仕様で、今回の文書追加は本番ソースを変更しない。
