# PDF パスワードの保存データ保護：提案

確認日：2026-10-10。これは方式選定の提案であり、暗号化の実装・テスト成功を示さない。現行の [PDF パスワード仕様](pdf-passwords.md) は平文保存のまま。

## 現行実装と保護対象

`src/common/password-store.ts` の `LocalPasswordStore` は `vimdf.passwords.v1` に `{version:1,autoFill,records,remembered}` を JSON として保存し、`records[].password` は入力された文字列のまま。`chrome.storage.local`、`TRUSTED_CONTEXTS`、インコグニート分離、Web Lock は使うが、パスワード保管の暗号化はしない。Options の伏字は画面上の表示だけ。PDF 自体の暗号化とも別の話になる。

今回想定する攻撃は、拡張機能の保存ファイル、ブラウザのプロファイルやバックアップを第三者がコピーし、オフラインで読むこと。保存ファイルだけで秘密を取り出せないようにする。ロック解除中のメモリ、入力の盗聴、マルウェアや改変された拡張機能まで同じ仕組みで保護できるとはしない。弱いマスターパスワードへのオフライン推測も完全には防げない。

PDF.js の復号には元の PDF パスワードが必要なので、不可逆なハッシュだけを保存する方式では自動入力できない。元の値を復元できる暗号化と、その鍵の管理が必要。

## 方式の比較

| 方式 | 保存データ流出時の保護 | 操作・導入 |
| --- | --- | --- |
| 永続保存しない | 保存済み秘密が存在しない | PDF を開くたび入力。拡張だけで対応可能 |
| マスターパスワードで暗号化 | 強いマスターパスワードと適切な鍵導出により、保存ファイルだけでは復号困難 | 起動後に解錠し、解錠中は既存の自動入力を利用。拡張だけで対応可能 |
| OS の秘密保管と連携 | 鍵を拡張の保存データから分離できる。OS アカウント等の保護にも依存 | Native Messaging 等の連携用アプリ、OS ごとの導入・管理が必要 |

VimDF の候補は、永続保存しない利用を維持したうえで、保存を利用する人にマスターパスワード方式を提供すること。OS 連携は外部アプリを配布・管理する別スコープとする。

## 推奨案の境界

- Web Crypto の AES-256-GCM により、登録名・PDF パスワード・文書との関連付けを含む vault の内容を認証付き暗号化する。鍵をソースコードへ埋め込んだり、暗号文とともに平文保存したりしない。
- 鍵は利用者のマスターパスワードとランダムな salt から導出する。ブラウザ標準だけで構成する案は PBKDF2-HMAC-SHA-256。初期候補は 600,000 回以上とし、代表環境の解錠時間を実測して決定する。Argon2id は有力だが、採用時は保守される実装、WASM・メモリ・配布を別途評価する。PBKDF2 のこの値は OWASP の公開基準を参考にした候補であり、VimDF の性能検証済み値ではない。
- salt は CSPRNG で生成した少なくとも 16 bytes、GCM IV は書込みごとに新しい 12 bytes。同じ鍵と IV の組合せを再利用しない。バージョン・暗号方式・鍵導出設定を検証し、認証対象に結び付ける。未知の形式、不正な長さ、過大な鍵導出設定は復号前に拒否する。
- 永続保存は暗号文、認証 tag、salt、IV、バージョン・導出パラメーターだけ。マスターパスワード、導出鍵、復号済み PDF パスワードを local / sync / IndexedDB / URL / ログへ保存しない。`TRUSTED_CONTEXTS` とインコグニート分離を維持する。
- 起動・再起動後はロック状態。利用者が明示的に解錠する。鍵は解錠中のメモリだけで保持し、手動ロック・一定時間の未使用で参照を破棄する。JavaScript の文字列や GC のため、メモリの完全なゼロ化を保証する文言は使わない。解錠を複数 Viewer で共有する方式と timeout の長さは実装前に決める。
- ロック中も保存を利用しない手入力で PDF を開ける。マスターパスワードを忘れたときは vault の初期化と再登録で回復し、秘密を復元する裏口は設けない。初期化は登録フォルダ、PDF 本体、マーク・ハイライトを消さない。
- マスターパスワードの変更は旧パスワードで解錠してから再暗号化し、保存成功後だけ新しい設定を有効にする。誤った解錠、改ざん、保存失敗で vault を空にして自動上書きしない。
- 現行 v1 の移行は明示的な設定後に行う。暗号化した保存の成功を確認してから旧平文レコードを削除し、途中失敗では再試行可能にする。旧版へのダウングレードで平文を再生成しない。既存のバックアップや流出済みコピーは後から暗号化して保護できない。

## 方式が決まった後に追加する検査

1. 正しいマスターパスワードで登録・解錠・PDF 自動入力でき、保存データ全体にテスト用の秘密や鍵が存在しない。
2. 誤ったパスワード、暗号文 / tag / IV / salt / metadata の改ざんを拒否し、元データを変更しない。
3. 同じ内容の再保存でも新しい IV を用い、同じ key / IV を再利用しない。形式と KDF 入力の境界を検査する。
4. ロック・timeout・再起動・インコグニートで自動入力を停止し、遅い解錠・読み込みが秘密を再公開しない。手入力は利用できる。
5. マスターパスワード変更・保存失敗・同時更新・v1 移行の途中失敗を検査する。成功後は平文保存が残らず、失敗はデータ喪失へ変わらない。
6. PDF 選択、help、CSS 更新、複数タブの遷移が鍵や秘密を永続化・ログ出力しない。パスワード入力とキー操作の所有を維持する。
7. 初期化は vault だけに作用し、登録・PDF の他の保存データを保持する。

UI 要件の追加テストに暗号化を実装済みと見なす検査を混ぜない。今回のパスワード保存コードと既存テストは変更していない。
