# PDF パスワード保管庫：要件と仕様

更新日：2026-10-10。マスターパスワードによる暗号化保管、暗号化バックアップ、明示的な平文エクスポートを採用する方針。これは実装対象の仕様であり、実装済み・テスト成功を示さない。現行の [PDF パスワード仕様](pdf-passwords.md) と `src/common/password-store.ts` は `vimdf.passwords.v1` への平文保存のまま。暗号化・解錠・エクスポート・復元の追加テストも未作成。

## 目的と対象

拡張機能の保存ファイル、ブラウザのプロファイル、バックアップを第三者がコピーしても、そのコピーだけでは登録済み PDF パスワードを容易に取り出せないようにする。保存を使わず、PDF を開くときだけ手入力する運用も維持する。

| 用語 | 役割 | 扱い |
| --- | --- | --- |
| マスターパスワード | 保管庫を解錠し、暗号鍵を導出する | VimDF は永続保存しない。利用者がパスワードマネージャー等で管理する |
| PDF パスワード | 個々の PDF を PDF.js で開く | 登録する場合は保管庫内に暗号化保存する |
| 保管庫 | 登録名、PDF パスワード、設定、文書との関連付けの集合 | 内容全体を暗号化保存する |
| 暗号化バックアップ | 保管庫を移行・復元するファイル | マスターパスワードと復号鍵を含めない |
| 平文エクスポート | 他のツールへ登録済みパスワードを移すファイル | 内容を読める人に PDF パスワードが見える |

VimDF 専用の長いランダムなマスターパスワードをパスワードマネージャーで生成・保存し、解錠画面へ貼り付ける運用を案内する。パスワードマネージャー自身のマスターパスワードとは別に作る。貼り付けを禁止しない。パスワードマネージャーの自動入力や固有 API との連携は前提にしない。

PDF.js には元の PDF パスワードが必要なので、ハッシュだけを保存する方式は使わない。保管庫の暗号化は PDF ファイル自体の暗号化や PDF パスワードを変更しない。

## 解錠と再入力

| 操作 | マスターパスワードの入力 |
| --- | --- |
| 保管庫の初期設定 | 新しい値と確認用の再入力 |
| ロックされた保管庫の解錠 | 必要 |
| 解錠中の PDF 自動入力、登録、編集、削除、並べ替え | 不要。メモリに保持する鍵を使う |
| 暗号化バックアップの出力 | 不要。ロック中でも保存済み暗号文を出力できる |
| 暗号化バックアップの検証・復元 | バックアップ作成時のマスターパスワードが必要 |
| 平文エクスポート | 毎回必要。解錠済みでも出力操作専用に再認証する |
| マスターパスワードの変更 | 現在の値、新しい値、確認用の再入力が必要 |
| 保存を使わない PDF の手入力 | 不要。PDF 自身のパスワードだけを入力する |
| マスターパスワードを失った保管庫の初期化 | 不要。秘密を復元できないことと対象を明示して確認する |

新規の永続保存には保管庫の作成を必要とし、暗号化処理の失敗を平文保存に切り替えない。マスターパスワードは空文字を拒否し、前後の空白や Unicode を加工しない。長さの下限は実装前に確定する。文字種の強制、切り詰め、勝手な正規化は行わない。

起動・再起動・秘密を保持する実行コンテキストの終了後はロック状態。鍵は解錠中のメモリだけで保持する。手動ロックと一定時間の未使用で鍵・復号済み登録・パスワード入力欄の参照を破棄する。再解錠しても登録内容は保持され、再登録は不要。複数 Viewer / Options 間の解錠共有方式、未使用時間と活動判定は実装前に確定する。JavaScript の文字列や GC のため、メモリの完全なゼロ化は保証しない。

ロックは、すでに開いた PDF を閉じたり閲覧位置・マーク・ハイライトを消したりする操作ではない。以後の保管庫アクセスと自動入力を停止する。ロック後に返る解錠・読込み・再認証結果は無効とし、秘密を再表示・出力しない。すでに PDF.js に渡した値を後から取り消せるとはしない。

## PDF 自動入力と画面操作

解錠中は既存の候補選択を維持する。文書で最後に成功した有効な登録、次に他の PDF への使用を許可した登録を設定順に各 1 回試す。全候補が失敗したときは手入力へ進む。全体の自動入力がオフなら解錠中でも候補を試さない。保存・関連付けは PDF の読込み成功後だけ行い、誤った候補を自動削除・上書きしない。

ロック中は保管庫の登録名・パスワード・文書との関連付けを読み出さず、「保管庫を解錠」と「保存せず手入力」を選べる。保存を選ぶには解錠または初期設定を必要とする。解錠を取り消しても手入力で開ける。パスワード不要の PDF で解錠を強制しない。保存失敗でも開けた PDF は維持する。

管理は既存の共通 Options の「PDF パスワード」に集約し、作成・解錠・ロック・マスターパスワード変更・暗号化バックアップ・復元・平文エクスポート・保管庫の初期化を用意する。PDF 選択画面へ Settings ボタンを追加しない。Options はカスタム CSS の対象外という既存方針を維持する。

パスワード入力は初期状態で伏字、表示切替は明示操作。Enter はそのダイアログだけを送信し、Esc / キャンセルはその操作だけを取り消す。入力・IME・ダイアログが一覧と Viewer の Vim キーより優先し、フォーカスを閉じ込め、終了後は呼び出し元へ戻す。エラーや一般のヘルプへ秘密を含めない。

## 暗号化保存

`chrome.storage.local` の新キー `vimdf.passwords.v2` にバージョン付き暗号化形式を保存する。`TRUSTED_CONTEXTS`、インコグニート分離、更新の排他制御を維持する。登録名、パスワード、ID、登録順、有効・共有フラグ、全体の自動入力設定、文書との関連付けを含む内容全体を Web Crypto の AES-256-GCM で認証付き暗号化する。

マスターパスワードを UTF-8 とランダムな salt から鍵へ導出する。初版の方式は PBKDF2-HMAC-SHA-256 とする。反復回数の候補は 600,000 回以上で、代表環境の解錠時間を測定して最終値と受け入れる範囲を確定する。これは OWASP の公開基準を参考にした候補であり、VimDF で性能検証済みの値ではない。利用者が任意の低い回数へ変更する設定は設けない。Argon2id や OS の秘密保管との連携は今回の対象外。

salt は CSPRNG で生成する少なくとも 16 bytes、GCM IV は書込みごとに新しい 12 bytes、認証 tag は 128 bits とする。同じ鍵と IV の組合せを再利用しない。マスターパスワード変更では新しい salt と鍵と IV を使う。

保存・バックアップの外側に置く情報は、形式識別子 `vimdf-password-vault`、形式バージョン `2`、暗号方式、鍵導出方式・反復回数・salt、IV、認証 tag を含む暗号文だけとする。バイナリ値は Base64 とする。形式・バージョン・アルゴリズム・鍵導出設定を認証対象へ結び付ける。IV と暗号文の変更も復号検証で拒否する。認証対象の正確なバイト列と JSON スキーマは暗号実装前に固定する。

マスターパスワード、導出鍵、復号済み PDF パスワードを `local` / `sync` / IndexedDB / URL / ログ / 一般ページの DOM / `postMessage` へ保存・公開しない。拡張機能の解錠・登録画面に必要な一時入力と PDF.js への引き渡しだけを許可する。専用の平文エクスポートは、後述の明示操作に限る例外。

未知の形式・バージョン・アルゴリズム、不正な Base64・長さ・構造、上限を超えるファイル・復号内容・鍵導出負荷は拒否する。高負荷な鍵導出や復号を始める前に外側の検証を済ませる。復号後も既存の登録数上限 100 件、非空 PDF パスワード、秘密文字列の重複禁止、ID の一意性、型、順序、関連付け先を検証する。大きさの具体的な上限は JSON スキーマと一緒に確定する。

## 暗号化バックアップと復元

通常のエクスポートは「暗号化バックアップ」を既定にする。保存済み `v2` の暗号化形式を、復号・再暗号化せず `vimdf-passwords-YYYYMMDD-HHMMSS.vimdf-vault.json` として出力する。時刻以外に登録名、PDF 名、URL、マスターパスワードをファイル名へ入れない。確定した 1 世代全体を出力し、未保存の編集を含めない。未作成、旧平文だけが存在、読込み失敗、外側の形式が不正な場合は出力しない。旧平文を「暗号化バックアップ」という名前で出力しない。

ロック中の出力にマスターパスワードは不要。ロック中は暗号文の真正性や内容を復号検証できないので、出力成功を「復元検証済み」と表示しない。ダウンロードの開始と完了・取消・失敗を区別し、出力の取消・失敗は保管庫を変更しない。出力用の一時 Blob / URL は終了後に解放する。

復元の流れは「ファイル選択 → 外側の検証 → 作成時のマスターパスワード入力 → 認証付き復号・内容検証 → 復元確認 → 保存」とする。新規保管庫への復元を許可する。既存保管庫への復元は、現在の保管庫を解錠したうえで置換対象と件数を確認する。初版は保管庫全体の置換とし、曖昧な重複統合は行わない。既存の値とバックアップのマスターパスワードが異なる場合は別々に入力する。

復元後のマスターパスワードはバックアップ作成時のものになる。必要なら復元後に変更する。過去のバックアップは過去の値で開くため、現在のマスターパスワード変更だけでは既存バックアップを無効化できないことを変更画面で案内する。

検証・確認・保存成功より前に既存保管庫を消さない。復元直前に対象の世代を排他制御下で再確認し、別画面から変更されていたら上書きせずやり直す。パスワード誤り、破損、改ざん、容量超過、取消、保存失敗では旧保管庫を保持する。成功時は旧解錠セッションを無効化し、復元した保管庫をロック状態にする。

バックアップは登録順・各フラグ・文書との関連付けを含めて復元するが、フォルダハンドルやアクセス権限、PDF 本体、マーク・ハイライト、カスタム CSS を含めない。ローカル文書の関連付けは元の root ID / path が一致するときだけ有効で、別端末で同名フォルダを選んだだけでは同一視しない。復元だけでフォルダを登録したりアクセスを要求したりしない。

## 平文エクスポート

暗号化バックアップと別の「平文でエクスポート」操作にする。出力ファイルを読める人に PDF パスワードが見えること、取り込み後に平文ファイルを削除する運用を出力画面に示す。ファイル削除で過去のコピーやバックアップまで消えるとは案内しない。

操作ごとに現在のマスターパスワードの再入力と出力確認を必要とする。直前に解錠した場合も省略しない。再認証は現在の保管庫の認証付き復号で検証し、現在の解錠状態だけを成功条件にしない。再入力と確認の両方が終わる前に平文 Blob やダウンロードを作らない。ロック中でも、この操作の解錠・再認証と確認を経て出力できるが、出力だけで通常の解錠状態へ切り替えない。

再認証の許可は 1 回の出力と、検証した保管庫の世代・形式・選択内容にだけ結び付ける。別画面での編集、復元、マスターパスワード変更、ロック、初期化、取消、ダイアログ終了で無効化する。出力直前に状態と世代を再確認し、古い成功結果で別の内容を出力しない。再試行は再認証からやり直す。

初版は全登録を登録順に UTF-8 の汎用 JSON で出力する。形式識別子 `vimdf-password-export`、バージョン `1` と `records: [{name, password, enabled, shared}]` を含める。無効な登録も含め、画面の絞り込みで出力対象を勝手に変えない。空白・Unicode・改行を保持する。マスターパスワード、暗号鍵、文書との関連付け・URL・root ID、PDF 本体は出力しない。汎用 JSON は他のパスワードマネージャーへの直接取り込みを保証しない。

パスワードマネージャー固有の CSV は、対象製品とインポート形式を決めて追加する。CSV の引用符処理だけでは表計算ソフトでの数式実行を防げず、秘密文字列へ接頭辞を勝手に付けるとパスワードが変わるため、形式未確定の汎用 CSV は初版で提供しない。平文の VimDF へのインポートは今回の対象外。

ファイル名は `vimdf-passwords-YYYYMMDD-HHMMSS.plaintext.json` とし、秘密由来の文字列を入れない。出力の取消・失敗で保管庫を変更しない。一時データと Blob / URL を終了後に解放し、秘密・再入力値をログ、エラー、一般の通知へ含めない。ダウンロード済みファイルを VimDF が後から暗号化・回収できるとはしない。

## マスターパスワード変更・移行・初期化

マスターパスワード変更は現在の値で再認証し、新しい値と確認用の値が一致した場合だけ新しい salt / 鍵 / IV で再暗号化する。排他制御下で世代を再確認し、新しい保存の成功と読み戻し検証後だけ有効にする。成功後はすべての旧解錠・再認証を無効化してロックする。誤入力・保存失敗・競合は現在の保管庫を保持する。外部に出した古いバックアップを変更しない。

現行 `v1` の移行は Options でマスターパスワードを設定して明示的に実行する。登録、順序、フラグ、全体設定、文書との関連付けを保つ。排他制御下で暗号化した `v2` を保存して読み戻し・復号検証を行ってから旧平文キーを削除する。旧平文の削除に失敗した場合は「移行完了・平文が残っていない」と表示せず、残存と再試行を案内する。

移行途中で `v1` と `v2` が両方ある場合は `v1` を自動入力・通常編集へ使わない。`v2` を検証して移行を再開し、破損を空保管庫として上書きしない。旧平文を消すまで暗号化バックアップ・平文エクスポート・通常編集の有効化を完了しない。新実装は平文保存への切替や旧版用の平文再生成を行わない。旧拡張版の挙動は保証せず、ダウングレードを案内しない。既存の平文バックアップや流出済みコピーは後から保護できない。

マスターパスワードを忘れた場合に秘密を復元する裏口は設けない。保管庫だけの初期化と PDF パスワードの再登録で再開する。初期化は保管庫と移行中の平文残存を対象にし、登録フォルダ、PDF 本体、マーク・ハイライト、カスタム CSS を保持する。対象と復元不能になる内容を確認する。削除失敗では成功表示しない。初期化は PDF パスワードの個別編集・削除とも、フォルダ登録の解除とも別の操作。

インコグニートでは通常プロファイルの保管庫を読まず、解錠・保存・エクスポート・復元・移行・変更・初期化を無効にする。保存せず PDF パスワードを手入力することはできる。

## 保護の限界と失敗時の原則

解錠中のメモリ、入力の盗聴、マルウェア、改変された拡張機能、パスワードマネージャー自体の侵害まで保管庫の暗号化だけで防げるとはしない。弱いマスターパスワードへのオフライン推測も完全には防げない。認証失敗は「パスワードが違うか、保管庫が破損しています」とし、空の内容を生成して元データを上書きしない。

更新・移行・変更・復元は、保存対象の世代確認と書込みを共通の排他制御下で行う。遅い非同期処理がロック・取消・別画面の更新をまたいだ場合は、古い状態の表示・秘密の出力・未開始の保存を止める。すでに保存 API へ送った書込みは後から取り消せると保証せず、確定状態を読み戻して扱う。読込み・書込み・出力の失敗を区別し、秘密を含まない説明を出す。

## 受け入れ条件と追加するテスト

以下は追加予定の契約であり、現行の 34 件のパスワードテストや UX-01〜13 の成功を暗号化・出力の検証として数えない。まだテストは作成していない。

| ID | 検査する条件 |
| --- | --- |
| SEC-01 | 作成・解錠・登録・編集・再保存後、永続データにマスター・鍵・PDF パスワード・登録名・文書リンクの平文がなく、正しく復号できる |
| SEC-02 | マスター・PDF パスワードの空白・Unicode・改行を保持し、パスワードマネージャーから貼り付けできる |
| SEC-03 | 正しい値で解錠し、誤入力・破損・改ざんでは解錠・上書き・自動入力しない |
| SEC-04 | 新規書込み・変更で IV を再利用せず、salt / tag / metadata / IV / 暗号文の変更を拒否する |
| SEC-05 | 不正形式・未知バージョン・過大入力・過大 KDF を高負荷処理前に拒否し、復号後の登録・関連付けも検証する |
| SEC-06 | 起動・再起動・手動ロック・timeout で秘密のアクセスを停止し、遅い結果が再公開しない。開いた PDF の閲覧状態は保つ |
| SEC-07 | 解錠中の既存候補順・有効/共有/全体設定・成功後保存が動作し、通常操作でマスターを再入力しない |
| SEC-08 | ロック中・解錠取消・未作成でも保存なしの手入力ができ、パスワード不要の PDF では解錠を要求しない |
| SEC-09 | 入力・IME・Enter / Esc・フォーカス・help・CSS の操作が秘密を公開せず、一覧・Viewer のキーと競合しない |
| SEC-10 | ロック中と解錠中で同じ確定済み暗号化形式を出力し、復号・マスター入力・未保存編集の出力をしない |
| SEC-11 | 未作成・旧平文・読込み失敗・外側の不正形式・移行未完了から暗号化バックアップを作らない |
| SEC-12 | 暗号化バックアップの取消・失敗・ファイル名・一時 URL 解放を確認し、元保管庫を変更しない |
| SEC-13 | バックアップを正しい作成時マスターで復元し、全登録・順序・設定・関連付けを保ち、復元後はロックする |
| SEC-14 | 復元の誤入力・改ざん・不正内容・取消・競合・保存失敗で既存保管庫を維持する |
| SEC-15 | 異なる現行/バックアップマスターの置換、旧バックアップ、別端末の root ID を検査し、フォルダ・権限を自動登録しない |
| SEC-16 | 平文出力は解錠済みでも毎回マスターと明示確認を必要とし、誤入力・取消で平文 Blob / ダウンロードを作らない |
| SEC-17 | 平文出力の許可を 1 回・同じ世代に限定し、編集・ロック・初期化・変更・復元・終了・遅い結果で無効化する |
| SEC-18 | 平文 JSON の全登録・順序・値・フラグを保持し、マスター・鍵・URL・関連付け・PDF 本体を含めない |
| SEC-19 | 平文出力の失敗・取消・後片付け・秘密を含まないエラーを検査し、ロック中からの出力で通常解錠しない |
| SEC-20 | マスター変更の旧値再認証・新値一致・保存成功・失敗・競合・セッション失効を検査し、旧バックアップは旧値のまま開く |
| SEC-21 | v1 移行の保存・読み戻し・復号・削除、各段階の失敗と再起動、平文残存、再試行で喪失・平文への切替がない |
| SEC-22 | 同時編集・保存容量エラー・遅い取消を検査し、元保管庫を維持して成功を誤表示しない |
| SEC-23 | 初期化は通常・移行途中の秘密だけを削除し、フォルダ・PDF・マーク・ハイライト・CSS を保持する |
| SEC-24 | インコグニートでは通常保管庫への全アクセス・出力・破壊操作を禁止し、手入力だけを利用できる |

## 実装前に確定する項目

- 解錠状態を共有する範囲と鍵の保持場所、複数画面からのロック・変更・復元・初期化の失効通知。
- 自動ロックの未使用時間・活動判定、マスターパスワード長の下限。
- PBKDF2 の実測後の反復回数・受入範囲、JSON スキーマ・認証対象バイト列、ファイル/復号内容のサイズ上限。
- パスワードマネージャー固有の直接取り込みを追加する場合の対象製品と形式。初版の汎用平文 JSON とは分ける。

これらを決める前に、解錠が全タブで共有される、自動入力が起動中ずっと使える、特定のパスワードマネージャーへ直接取り込める、と案内しない。
